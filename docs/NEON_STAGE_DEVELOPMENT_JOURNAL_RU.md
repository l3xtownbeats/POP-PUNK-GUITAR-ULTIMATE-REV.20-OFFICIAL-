# NEON STAGE — журнал разработки интерфейса и окон REV.20

**Проект:** POP PUNK GUITAR ULTIMATE REV.20  
**Эталон:** семь утверждённых изображений NEON STAGE 01–07 — единая интерфейсная система.  
**Тема по умолчанию:** SKIN-1 / NEON STAGE PREMIUM / `skin-053`.  
**Ветка:** `fix/neon-stage-graphite-cyan-blue`.

## 1. Назначение и неизменяемые правила

NEON STAGE — не отдельный альтернативный скин, а утверждённый внешний вид основного инструмента. Все семь макетов 01–07 описывают одну систему экранов, материалов, компонентов и состояний.

Обязательные ограничения:

- Точное следование утверждённым макетам и их геометрии; не придумывать новый дизайн и не заменять его типовым интерфейсом.
- Цветовая система: графит, cyan и electric blue. Не вводить фиолетовый, пурпурный и magenta.
- Не менять DSP, аудиопоток, MIDI-поведение, имена/диапазоны параметров APVTS, идентификаторы тем и утверждённый состав 500 factory presets в рамках UI-работ.
- Динамические значения, названия пресетов, LCD, измерители и подписи остаются нативными JUCE-компонентами, а не запечёнными в картинку.
- PNG — основной формат готовой графики. SVG сохраняется до тех пор, пока проверенные PNG-замены не интегрированы и не прошли проверку.
- Никаких фиктивных текстур, растянутых миниатюр вместо master artwork и поддельных checksum.

## 2. Архитектура интерфейса

### 2.1 Главный экран / NEON STAGE Console
Файл реализации: `Source/PluginEditor.cpp`, объявление компонентов — `Source/PluginEditor.h`.

Основные зоны:
1. Верхняя шапка: название продукта, выбранный пресет, поиск/выбор и категория.
2. Центральный LCD/status display: актуальный режим, имя/состояние звука, сообщения о библиотеке и загрузке.
3. Секция AMP / PERFORMANCE: девять параметрических регуляторов.
4. FX CHAIN: семь переключателей эффектов.
5. PLAYBACK: режим MELODY/PATTERN, параметры запуска и MIDI-клавиатура.
6. Performance display: состояние сыгранных нот/аккорда и выходной уровень.
7. Нижняя панель действий: Import Guitar, AutoChords, Skin, Settings и About. Нереализованные сервисы должны оставаться явно отключёнными, а не изображать работающие функции.

### 2.2 Девять регуляторов
Каждый регулятор — настоящий JUCE rotary Slider с APVTS SliderAttachment, а не декоративная картинка.

| № | Подпись | APVTS ID |
|---:|---|---|
| 1 | GAIN | `ampGain` |
| 2 | TREBLE | `eqHigh` |
| 3 | MID | `eqMid` |
| 4 | BASS | `eqLow` |
| 5 | VELOCITY | `velocity` |
| 6 | DYNAMICS | `dynamics` |
| 7 | SWING | `swing` |
| 8 | HUMANIZE | `humanize` |
| 9 | ACCENT | `accent` |

Ожидаемое поведение:
- drag мышью/пером меняет реальное значение параметра;
- указатель/дуга поворачивается синхронно с APVTS и automation host;
- числовое значение доступно в подписи/tooltip и не теряется при смене темы;
- состояния artwork: default, hover, dragged, disabled; при отсутствии подходящего authored-state используется безопасный визуальный fallback;
- при изменении значения не перерисовывать весь редактор без необходимости.

### 2.3 Семь переключателей FX
Каждая кнопка использует APVTS ButtonAttachment и реальное toggle-состояние.

| № | Эффект | APVTS ID |
|---:|---|---|
| 1 | COMPRESSOR | `compressorOn` |
| 2 | EQ | `eqOn` |
| 3 | DISTORTION | `distortionOn` |
| 4 | CHORUS | `chorusOn` |
| 5 | DELAY | `delayOn` |
| 6 | REVERB | `reverbOn` |
| 7 | CABINET IR | `cabinetOn` |

Состояния каждой кнопки:
- OFF — приглушённый графитовый вид;
- hover — подсветка границы/поверхности;
- pressed — короткая визуальная реакция на нажатие;
- ON/active — устойчивое cyan/electric-blue свечение и видимый индикатор включения;
- disabled — контрастно приглушённое состояние, если действие действительно недоступно.

Нажатие должно переключать реальный параметр FX, а не только менять цвет. Внешний вид всегда отражает APVTS, включая automation и восстановление проекта.

### 2.4 Режимы MELODY / PATTERN
Это взаимоисключающие табы, связанные с APVTS `playMode`.
- MELODY: активный таб светится, PATTERN отображается выключенным.
- PATTERN: активный таб светится, MELODY отображается выключенным; открывается окно PATTERN / RHYTHM.
- При загрузке проекта выбранное состояние восстанавливается из APVTS.
- Переключение через ComboBox, MIDI/host automation или табы должно синхронизировать одну и ту же пару состояний.
- Переключение режима не должно создавать второй независимый источник состояния.

## 3. Окна и панели

### 3.1 Preset Browser
Встроенная зона главного экрана:
- каталог factory presets и категории;
- поиск и фильтрация;
- выбор пресета обновляет реальные параметры;
- отображаемые имя, стиль, режим и артикуляция соответствуют выбранному пресету;
- прокрутка и поиск не должны блокировать аудиопоток.
- Сохранить единый банк из 500 factory presets; не дублировать его при разделении UI и preset engine.

### 3.2 FX EDIT / NEON STAGE
Окно детального редактирования FX, открывается из FX chain.
- Отображает параметры выбранной группы эффекта.
- Все параметры связаны с реальным processor/APVTS.
- Переключение FX-группы не создаёт копии состояния и не сбрасывает настройки.
- Внешний вид, заголовки, поля, переключатели и слайдеры следуют палитре NEON STAGE.

### 3.3 PATTERN / RHYTHM
Окно редактирования ритмического режима.
- Содержит элементы выбора/настройки ритмического рисунка и артикуляции, предусмотренные текущим backend.
- Видимые элементы управления не должны обещать недоступную функцию.
- Режим и значения должны согласовываться с главным экраном и preset metadata.

### 3.4 AUTOCHORDS / HARMONY WORKSPACE
Окно настройки тональности и гармонии.
- Отображает корневую ноту, лад и аккордовую информацию.
- Chord diagram обновляется по состоянию параметров/MIDI.
- UI обновляется безопасно, без чтения несинхронизированных данных из аудиопотока.

### 3.5 IMPORT GUITAR
Окно загрузки пользовательской SFZ-библиотеки.
- Выбор SFZ и связанных sample-файлов.
- Проверка путей и корректности файлов до загрузки.
- Отчёт об ошибках и статус библиотеки.
- Не включать в дистрибутив сторонние samples без подтверждённых прав на распространение.

### 3.6 VISUAL SKIN GALLERY
Окно выбора одной из 16 тем.
- Поиск, фильтр, избранное, временный preview, Apply и Cancel.
- Предпросмотр не должен сохранять тему до подтверждения Apply.
- SKIN-1 остаётся NEON STAGE PREMIUM и использует стабильный ID `skin-053`.
- Карточки декодируют preview лениво, только когда нужны на экране.

### 3.7 SETTINGS
Окно пользовательских настроек интерфейса:
- масштаб workspace;
- расстояние между панелями;
- восстановление стандартного вида;
- переход в Skin Gallery.
Настройки интерфейса сохраняются отдельно от параметров звука и не меняют DSP.

### 3.8 ABOUT
Окно сведений о версии, формате, библиотеке и ограничениях лицензирования.

### 3.9 Multi-window workspace
Реализация: `Source/UI/PPGUMultiWindowWorkspace.h` и соответствующий .cpp.
- Независимые закрываемые панели, масштабирование, раскладка/плитка, изменение порядка и восстановление геометрии.
- Каждая панель получает активную палитру через theme-aware интерфейс.
- Окна не владеют аудиосостоянием и не создают параллельные копии параметров.

## 4. Визуальная система и интерактивные состояния

### 4.1 LookAndFeel
`PPGUPremiumLookAndFeel` отвечает за отрисовку rotary controls, linear sliders, кнопок, ComboBox и текстовых полей. Для NEON STAGE использовать:
- authored PNG control states;
- sprite atlases и координатный manifest;
- живой указатель rotary и живые подписи поверх графического основания;
- градиенты/свечение только в пределах утверждённой палитры и макета.

### 4.2 Контракт состояний
Минимальная матрица проверки для интерактивного элемента:
- default;
- hover;
- pressed;
- active/on;
- disabled;
- dragged — для rotary/slider.

Если состояние не применимо, это явно отмечается в control-state manifest. Не подменять pressed и active одним и тем же состоянием.

### 4.3 Текущая логика активных табов
В коммите `0285a567fd137cc503e5ea44f32e4a0abce96cda` MELODY/PATTERN переведены в взаимоисключающие toggle tabs:
- оба отражают APVTS `playMode`;
- выбранный режим получает active/toggle artwork через LookAndFeel;
- начальное состояние синхронизируется при создании редактора;
- смена режима инициирует repaint обоих табов.

### 4.4 Реализация интерактивной подсветки — 21.11.2026

В рабочей ветке добавлено уточнение runtime-отрисовки без изменения утверждённой геометрии, DSP или APVTS-контрактов:

- Rotary controls продолжают использовать authored NEON STAGE PNG как основу; поверх неё нативно рисуются value-track, cyan/electric-blue value arc с мягким glow и указатель. Угол и дуга вычисляются из текущего normalized value JUCE Slider, поэтому визуальное положение следует за APVTS/host automation.
- MELODY и PATTERN получили отдельный LookAndFeel path `mode_tab`. Он использует состояния artwork `mode_selector`; активное состояние берёт нейтральную основу и добавляет динамический cyan indicator/glow. Это исключает ошибочное повторное использование FX rocker atlas для двух режимов.
- Взаимоисключающее состояние режимов остаётся производным от единственного APVTS `playMode`; ComboBoxAttachment, табы и восстановление проекта используют один источник истины. Сами табы работают как momentary selectors (`setClickingTogglesState(false)`): они не могут самостоятельно выключить уже выбранный режим повторным нажатием; закреплённую подсветку выставляет только `modeBox.onChange` по APVTS.
- Семь FX-переключателей сохраняют ButtonAttachment к исходным APVTS IDs; их OFF/ON и hover/pressed/disabled визуальные состояния определяются текущим состоянием JUCE Button и Skin-1 artwork/atlas.
- Добавлены регрессионные проверки приоритетов default/hover/pressed/active/disabled в `tests/ThemeManagerTests.cpp`.
- Добавлен `tools/validate_neon_stage_ui_contract.py` и запуск этого контракта в Windows native CI. Скрипт проверяет количество и порядок APVTS IDs, реальные attachment bindings, синхронизацию режимов, dedicated mode renderer, rotary value arc/pointer и наличие реализаций вспомогательных окон.

**Граница подтверждения:** source changes и автоматические проверки подготовлены; пока Windows CI не завершит сборку и CTest, а runtime не будет проверен в FL Studio 20, фактическая интерактивность в хосте не считается принятой.

## 5. Современные инженерные подходы

Применять новые средства там, где они повышают надёжность, не ломая совместимость JUCE 7/9 и Windows x64:

1. **Единый source of truth:** APVTS для параметров, manifest для ассетов, theme registry для тем, один preset catalog для всех окон.
2. **GPU-friendly compositing:** кэшированные растровые слои и atlas drawing; не декодировать PNG/SVG в paint() и не создавать тяжёлые blur/shadow эффекты на каждом кадре.
3. **HiDPI:** отрисовка с учётом масштаба экрана и authored 2x/4x assets; сохранять чёткость текста и указателей.
4. **Thread safety:** никаких файловых операций, блокировок, выделения памяти и тяжёлой графики в audio callback. Theme loading и декодирование — только message/control thread.
5. **Repaint discipline:** repaint только изменившихся компонентов; meter обновлять по ограниченной частоте и с порогом изменения уровня.
6. **Accessibility:** читаемые значения, keyboard focus, tooltip, достаточный контраст; активное состояние различается не только цветом.
7. **Reduced motion / Eco:** свечение и анимация ограничиваются, когда включён Eco/reduced-motion режим; функциональность переключателей не меняется.
8. **Deterministic assets:** проверка SHA-256, PNG CRC, размеров, альфа-канала, путей и atlas bounds на CI.
9. **Compatibility matrix:** Windows x64 + JUCE 7.0.12 и JUCE 9.0.6; фиксировать версии toolchain/dependencies.
10. **Automated UI QA:** проверка количества controls, component IDs, APVTS bindings, toggle states, layout bounds, asset decoding и screenshot/regression snapshots.
11. **Performance QA:** измерять repaint frequency, idle CPU, peak UI CPU, memory footprint, resize cost и открытие/закрытие панелей.
12. **Host acceptance:** отдельная проверка VST3 в FL Studio 20; зелёный CTest сам по себе не доказывает host acceptance.
