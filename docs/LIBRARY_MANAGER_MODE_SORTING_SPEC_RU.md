# POP PUNK GUITAR ULTIMATE — спецификация сортировки Library Manager

Статус: **БАЗОВАЯ СПЕЦИФИКАЦИЯ, УТВЕРЖДЕНА ПОЛЬЗОВАТЕЛЕМ**
Ветка: `feature/virtual-riff-extraction`

## 1. Назначение

Library Manager готовит библиотеку не как общий аудиоархив, а как набор проверяемых музыкальных материалов для реальных движков POP PUNK GUITAR ULTIMATE. Один исходный файл может дать несколько независимых кандидатов для разных режимов, но каждый кандидат обязан ссылаться на исходник и точный диапазон исходных сэмплов.

Сортировка не доказывает автоматически, что материал является гитарой, конкретной нотой, аккордом, аппликатурой, техникой игры или лицензированным контентом. Автоматические результаты — только кандидаты до прослушивания и проверки.

## 2. Основные ветви сортировки

### A. SAMPLE MODE — отдельные звуки

Назначение: воспроизведение отдельных нот и аккордовых атак с MIDI-клавиатуры.

Подкатегории:
- `SINGLE_NOTES` — отдельные ноты; нота и струна только после подтверждения.
- `POWER_CHORDS` — пауэр-аккорды; корень, состав и аппликатура только после проверки.
- `CHORD_VOICINGS` — подтверждённые аккордовые аппликатуры.
- `PALM_MUTE` — приглушённые атаки/ноты/аккорды.
- `OPEN_NORMAL` — открытая/обычная артикуляция.
- `CLEAN`, `CRUNCH`, `DISTORTION_HIGH_GAIN` — тембровые группы.
- `ACOUSTIC` — акустические ноты и аккорды.
- `LEAD_GUITAR` — одиночные лид-звуки и подтверждённые артикуляции.

Обязательные данные для готовой карты: MIDI note, диапазон, струна/лад при подтверждении, velocity layer, articulation, round-robin/take при наличии, sample rate, channels, subtype/format, исходный путь и hash. Неопределённые значения остаются `UNKNOWN`, а не угадываются.

### B. PATTERN MODE — ритмические исполнения

Подкатегории:
- `POP_PUNK_DOWNSTROKE`
- `PALM_MUTE_8TH_NOTES`
- `POWER_CHORD_RHYTHM`
- `PUNK_ROCK_RHYTHM`
- `FAST_DOWNSTROKE`
- `ALTERNATIVE_PUNK_RHYTHM`
- дополнительные проверенные пользовательские и заводские рисунки.

Разделять:
1. устойчивые повторяющиеся ритмические рисунки — кандидаты Pattern;
2. нерегулярные выразительные фрагменты — отдельные Phrase-кандидаты, не Pattern автоматически;
3. широкие RMS active regions — только технические области сигнала, не музыкальные рисунки.

Для Pattern сохранять последовательность атак/событий, временные позиции, границы, длительность, предполагаемый BPM только при достаточной надёжности, иначе `UNKNOWN`. Не растягивать и не квантизировать исходник автоматически.

Начальная MIDI Key Switch раскладка:
- C1 — Pop Punk Downstroke
- C#1 — Palm Mute 8th Notes
- D1 — Power Chord Rhythm
- D#1 — Punk Rock Rhythm
- E1 — Fast Downstroke
- F1 — Alternative Punk Rhythm

Это управляющие клавиши, не ноты инструмента. Фактические MIDI note numbers и октавные подписи должны быть проверены в FL Studio 20; диапазон переключателей не должен пересекаться с диапазоном игры аккордов.

### C. MELODY MODE — мелодические материалы

Подкатегории:
- `MELODY_LINES` — подтверждённые мелодические линии;
- `MELODY_PHRASES` — отдельные фразы;
- `LEAD_RIFFS` — лид-риффы;
- `NOTE_SEQUENCES` — последовательности отдельных нот;
- `ONE_PITCH_RHYTHM_SOURCE` — источник ритма для One Pitch, если ритмическая последовательность подтверждена.

Монофонический pitch tracker формирует только pitch candidates. Для полифонических/искажённых гитарных сигналов нельзя выдавать его оценки за точную транскрипцию.

### D. PHRASE / RIFF / ENDING / SLIDE

Эти типы ведутся отдельными метками исполнения, не сваливаются в Pattern:
- `RIFF_PHRASE` — подтверждённый рифф/фраза;
- `MELODY_PHRASE` — мелодическая фраза;
- `ENDING` — музыкальное окончание;
- `SLIDE_TRANSITION` — слайд/переход;
- `LEGATO_TRANSITION` — легатный переход.

Автоматический сегментатор может предложить точные диапазоны, но тип исполнения подтверждается прослушиванием и ручной разметкой.

## 3. Связь с режимами VST3

| Режим движка | Что готовит Manager |
|---|---|
| Strumming | Аккордовые voicings, направления/атаки струн, ритмические Pattern |
| Arpeggio | Проверенные chord voicings, порядок/время струнных атак |
| Riff | Riff/phrase candidates, ноты/интервалы после проверки |
| Melody | Проверенные note sequences и melodic phrases |
| Phrase | Phrase events и точные границы |
| One Pitch | Ритмический профиль Phrase/Pattern без автоматического утверждения высоты |
| Chord | Проверенные составы аккордов и voicings |
| Auto Chords | Проверенные chord maps и диапазоны MIDI |
| Pattern | Повторяемые ритмические исполнения и event timing |
| Ending | Проверенные ending phrases |
| Slide | Проверенные slide/transition samples или события |

Менеджер подготавливает данные для движка, но сам не подменяет runtime-распознавание MIDI-аккордов и выбор аппликатур в VST3.

## 4. Разбор длинных Guitar Loops

Каждый длинный WAV анализируется по независимым дорожкам:
- повторяющиеся чистые рисунки → Pattern candidates;
- нерегулярные выразительные группы атак → `IRREGULAR_GUITAR_LOOP_SEGMENTATION` Phrase candidates;
- отдельные ноты/атаки → Sample candidates только при достаточных границах и подтверждении;
- мелодические последовательности → Melody candidates при подтверждённой транскрипции;
- тишина, шум, обрезанные атаки и бессмысленные фрагменты → reject/review, не FACTORY.

Не использовать весь длинный loop как единый Pattern. Не путать RMS активный участок с риффом. Не транспонировать целый loop как замену chord engine.

## 5. Структура подготовки библиотеки

Кандидаты и проверенные материалы должны иметь независимые назначения:

`Samples/FACTORY/<STYLE>/WAV/<INSTRUMENT>/<ROLE>/<TONE>/`

Стили:
- `POP_PUNK`
- `PUNK_ROCK`
- `ALTERNATIVE_ROCK`
- `MELODIC_PUNK`
- `SKATE_PUNK`
- `EMO_POP_ROCK`

До утверждения материал остаётся в исходной `Import Sample Guitar` или в отдельном staging/review-слое Manager. Manager не перемещает, не переименовывает и не удаляет оригиналы. Физическое копирование производных файлов возможно только в управляемый staging/factory workflow после явного подтверждения пользователя.

## 6. Обязательные поля кандидата

- source path и относительный путь;
- source SHA-256;
- точные `source_start_sample` и `source_end_sample`;
- sample rate, channels, sample format/subtype;
- duration и event/onset timestamps;
- candidate type и target engine mode;
- note/chord/key/tempo/voicing/articulation — значение и confidence либо `UNKNOWN`;
- analysis algorithm/version;
- review status;
- license status и evidence reference;
- derived asset hash, если создан производный файл;
- `source_audio_modified=false`.

Нельзя восстанавливать точное число кадров из округлённой длительности, если его можно прочитать из метаданных исходного файла.

## 7. Review и лицензирование — жёсткий шлюз

Автоматическая классификация не переводит файлы в FACTORY.

Для допуска WAV в FACTORY обязательны оба независимых статуса:
- `REVIEWED` — человек прослушал и подтвердил категорию, границы, музыкальную пригодность и разметку;
- `LICENSE_APPROVED` — есть явное подтверждение лицензии и доказательство, что разрешено включение/распространение исходных sample assets в составе плагина.

Иначе материал остаётся в staging/review. Неизвестная лицензия = `UNREVIEWED`, а не разрешение.

## 8. Производительность и сохранность исходников

- По умолчанию один worker; жёсткий предел — два.
- Ограниченная память, потоковое чтение и кэш анализа с версией алгоритма.
- Повторно использовать валидные результаты для неизменённых файлов.
- Раздельно включать анализ Sample, Pattern и Melody, чтобы не выполнять ненужные дорогие проходы.
- Отмена и возобновление не должны портить отчёты/кэш.
- SHA-256 и метаданные не заменяют проверку музыкального содержимого.
- Никаких автоматических удалений дубликатов.
- Оригинальные файлы только читаются.

## 9. Текущий статус реализации

Этот документ фиксирует целевую схему сортировки. Наличие категории в спецификации не означает, что соответствующий классификатор, транскриптор, preview, MIDI map или VST3 runtime уже реализован и протестирован. Реализация и тесты должны отмечаться отдельно по каждому этапу.
