**Проект:** AUTO SOUND HUNTER MANAGER 3.0 и POP PUNK GUITAR ULTIMATE VST3

Этот документ фиксирует решения пользователя, явно утверждённые и подтверждённые им. Он является контрольной точкой для дальнейшей разработки и проверки проекта.

## 1. Единое значение утверждения

Следующие обозначения равнозначны и имеют одинаковую силу:

**БАЗА = УТВЕРЖДЕНО = ЗАФИКСИРОВАНО = ПОДТВЕРЖДЕНО = ПРИНЯТО = FINAL = LOCKED.**

То же значение имеют прямые формулировки пользователя: «утверждаю», «подтверждаю», «фиксирую», «оставляем так», «это окончательный вариант» и другие однозначные подтверждения решения.

Любое из этих обозначений означает, что решение принято пользователем, утверждено и включено в обязательную базу проекта. Это не разные уровни статуса и не последовательные стадии согласования.

## 2. Правила дальнейшей работы

1. Не пересматривать утверждённые решения по собственной инициативе.
2. Не заменять утверждённые элементы другими вариантами.
3. Не менять архитектуру, интерфейс, функции и визуальный стиль без прямого разрешения пользователя.
4. Все новые утверждения добавлять к существующей базе, не отменяя предыдущие.
5. Если новое требование противоречит ранее утверждённому, сначала согласовать изменение.
6. При продолжении разработки сверяться с единой утверждённой базой.

Прямое последующее разрешение пользователя может изменить конкретное решение. До такого разрешения действующая утверждённая база сохраняет силу.

## 3. Утверждённая архитектура продуктов

### 3.1. AUTO SOUND HUNTER MANAGER 3.0

Самостоятельная программа для подготовки гитарной библиотеки:

- импорт исходных материалов;
- сканирование;
- анализ;
- сортировка;
- обработка сэмплов;
- формирование структурированной библиотеки для отдельного VST3-инструмента.

Manager подготавливает библиотеку. Он не является самим музыкальным инструментом и не выполняет роль VST3-плагина.

#### IMPORT GUITAR — import handoff

IMPORT GUITAR must make selected external sources available to subsequent Manager stages. The approved non-destructive implementation is to create SHA-256-verified copies under the active `Samples/Import Sample Guitar` folder, preserve the original source files and their hierarchy/dependency paths, and register original-to-copy provenance. Failed imports roll back the incomplete batch. Re-import of an unchanged folder reuses its verified copy; if any file changes or is added, the complete folder is copied into a new batch so SFZ relative dependencies stay within one version. Previous batches remain for comparison/recovery, and altered previously verified copies are rejected. SCAN LIBRARY and START HUNTING process the verified copies. Archives remain opaque and are not automatically extracted.

## 3.2. POP PUNK GUITAR ULTIMATE VST3

Отдельный музыкальный инструмент, который загружает подготовленную Manager библиотеку и воспроизводит гитарные партии.

В плагине утверждены два главных режима:

- **MELODY**
- **PATTERN**

**AutoChords** не является третьим главным режимом. Он относится к **PATTERN** и открывается внутри него в дополнительном окне.

### 3.3. Обязательная граница продуктов

Manager формирует библиотеку; VST3 использует её для воспроизведения.

MELODY, PATTERN и AutoChords — элементы функциональности отдельного VST3-плагина. Они не являются режимами или главными разделами Manager. Не переносить эти режимы в интерфейс или архитектуру Manager.

Изменение этой границы допускается только по прямому разрешению пользователя.

## 4. Утверждённая база интерфейса Manager

### 4.1. Главный экран

На главном экране Manager остаются ровно шесть основных действий:

1. **IMPORT GUITAR**
2. **SCAN LIBRARY**
3. **START HUNTING**
4. **REVIEW QUEUE**
5. **BUILD LIBRARY**
6. **VERIFY / RECOVERY**

Вспомогательные функции сохраняются и открываются через меню или дополнительные окна. Они не превращаются в дополнительные главные действия.

### 4.2. Графическая тема

Утверждённый визуальный ориентир Manager — **NEON STAGE DEFAULT / SKIN 1**, в стиле графической темы плагина.

Не заменять её произвольной темой и не менять утверждённую визуальную базу без прямого разрешения пользователя.

## 5. Целевая платформа и требования к поставке Manager

- Целевая платформа: **Windows 10 x64**.
- Предусмотрена автономная Portable-поставка в ZIP.
- Portable-пакет должен содержать приложение и необходимые runtime-компоненты; отдельная установка Python на целевой машине не должна требоваться.
- Пользовательские данные должны храниться отдельно от исходников приложения и сохраняться между запусками.
- Также предусмотрена сборка установщика Windows EXE.
- Импорт, сканирование и анализ не должны самовольно изменять или удалять исходные аудиофайлы.

Наличие этих требований в утверждённой базе не означает, что соответствующая сборка или проверка уже выполнена.

## 6. Обязательность реализации утверждённой базы

**Каждое решение, обозначенное пользователем как БАЗА / УТВЕРЖДЕНО / ПОДТВЕРЖДЕНО / ЗАФИКСИРОВАНО / ПРИНЯТО / FINAL / LOCKED, является обязательным требованием к реализации.**

Утверждение — это не пожелание, не просто запись в документации и не разрешение оставить решение только на бумаге. Оно означает, что соответствующий элемент должен быть реализован в продукте в точном соответствии с утверждённой базой.

Для каждого утверждённого требования действует следующий порядок:

1. **УТВЕРЖДЕНО / ЗАФИКСИРОВАНО** — требование принято и обязательно к реализации.
2. **В РАЗРАБОТКЕ** — ведётся фактическая реализация; работу нельзя выдавать за завершённую.
3. **РЕАЛИЗОВАНО** — требуемая функция, интерфейс или поведение присутствуют в продукте.
4. **ПРОВЕРЕНО** — реализация прошла относящиеся к ней тесты и практическую проверку.
5. **ГОТОВО / READY** — реализация выполнена и проверена; имеются подтверждающие результаты.

Нельзя подписывать элемент как **ГОТОВО / READY**, если он только утверждён, описан в документации, присутствует в исходном коде без проверки или ожидает сборки/тестирования. Нельзя также оставлять утверждённое требование нереализованным и считать, что одной фиксации в документе достаточно.

Если требование утверждено, но не реализовано, оно остаётся обязательством разработки с честным статусом **НЕ РЕАЛИЗОВАНО** или **В РАЗРАБОТКЕ**, пока не будет фактически реализовано и проверено. Финализация проекта означает закрытие этих обязательств, а не только утверждение спецификации.
