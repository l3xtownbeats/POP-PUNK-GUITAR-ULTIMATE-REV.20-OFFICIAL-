# POP PUNK GUITAR LIBRARY MANAGER — версия 1.8.0

## Реализовано в ветке разработки

- Единый рекурсивный инвентаризатор Import Sample Guitar с SHA-256 и отчётами CSV/JSON.
- WAV-метаданные, базовый акустический анализ, onset/rhythm evidence и консервативная классификация кандидатов.
- Поиск повторяющихся ритмических кандидатов и физическое извлечение PCM WAV-фрагментов в staging.
- Исправлена передача source path + source SHA + вложенного pattern report в экстрактор.
- Транзакционный откат созданных клипов/манифестов, если извлечение завершается ошибкой или исходник изменился.
- Отдельный аудит Samples/OTHER и неподдерживаемых материалов импорта.
- OTHER-копирование выполняется только по явно заполненному other_decisions.json, с причиной, SHA-256, sidecar и журналом; по умолчанию только dry-run.
- FACTORY по-прежнему принимает только вручную проверенные и лицензированные материалы.
- Полный аудит зависимостей Import: проверяются исходники, манифесты staging, копии FACTORY/OTHER, SHA-256 и неучтённые staging WAV.
- Очистка оригиналов доступна только если каждый файл Import имеет проверенную зависимую копию, нет ошибок аудита, пройдена повторная свежая проверка и пользователь дал два подтверждения.
- GUI обновлён до версии 1.8.0: добавлены предпрослушивание WAV, OTHER audit/routing и полный cleanup audit.
- Добавлен шаблон OTHER_DECISIONS_TEMPLATE.json для ручного подтверждения маршрутизации.
- Добавлены Windows x64 PyInstaller one-folder build script и GitHub Actions workflow для сборки ZIP-артефакта.

## Безопасная политика OTHER

OTHER — отдельная библиотечная область для вручную признанных неподходящими материалов и материалов, требующих отдельного разбора. Классификатор огибающей не умеет достоверно доказать, что запись не является гитарой. Поэтому:
- UNKNOWN и низкая уверенность означают ручную проверку, а не автоматический отказ;
- невалидные/неподдерживаемые форматы получают статус OTHER_REVIEW_REQUIRED, но не перемещаются автоматически;
- сходство файлов не является основанием для удаления или объединения;
- оригиналы остаются в Import до успешной проверки копии и отдельного подтверждения очистки.

## Запуск

Из папки LibraryManager:

```bat
python manager_gui.py
```

Сборка портативной папки Windows 10/11 x64 (требуется Python 3.11 на машине сборки):

```bat
BUILD_PORTABLE_WINDOWS.bat
```

GitHub Actions также собирает ZIP по workflow Library Manager Windows Package.

## Что не следует считать завершённым или подтверждённым

Версия 1.8.0 не превращает эвристики в музыкальную истину. Необходимо отдельно учитывать:
- текущий анализатор работает прежде всего с WAV PCM; AIFF/FLAC/OGG/MP3 пока не декодируются полноценно;
- pattern detector предлагает повторяющиеся ритмические кандидаты, но не гарантирует правильные такты, downbeat, гармонию, музыкальные секции или полные риффы;
- полифонические ноты и аккорды остаются экспериментальными кандидатами;
- SFZ parser и валидатор нуждаются в расширенной проверке на реальных SFZ-библиотеках и всех edge cases;
- предпрослушивание/редактирование границ в GUI ещё не является полноценной review-средой;
- Windows package workflow должен успешно завершиться, а собранная папка должна быть проверена на чистой Windows-машине до объявления портативного релиза готовым;
- реальное качество классификации и сегментации нужно проверить на пользовательской библиотеке и прослушиванием.

## Контроль качества

GitHub Actions workflow Library Manager Tests компилирует Python-модули на Windows и запускает полный unittest regression suite. Отдельный workflow собирает портативный Windows ZIP. Успешный CI подтверждает прохождение автоматических тестов, но не заменяет прослушивание и проверку на реальной библиотеке.
