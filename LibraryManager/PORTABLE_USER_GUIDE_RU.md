# AUTO SOUND HUNTER MANAGER 3.0 — инструкция пользователя (Windows 10 x64)

## 1. Первый запуск

1. Распакуйте ZIP целиком в отдельную папку на любом диске. Не запускайте EXE изнутри архива.
2. Не вынимайте EXE из папки и не удаляйте служебную папку `_internal`.
3. Запустите `POP_PUNK_GUITAR_LIBRARY_MANAGER.exe`.
4. При первом запуске выберите реальную папку `Samples` или непосредственно `Import Sample Guitar`. Выбор сохраняется в пользовательских данных Manager.
5. Убедитесь, что внутри `Samples` существуют `Import Sample Guitar`, `FACTORY` и `OTHER`.
6. Новые исходные материалы добавляйте в `Samples/Import Sample Guitar`. Не помещайте туда отчёты Manager или временные файлы.

Python, pip и PyInstaller на пользовательском ПК не нужны. Переносите всю распакованную Portable-папку вместе с `_internal`, `portable.mode` и созданной `UserData`. Если папка приложения защищена от записи, Manager использует постоянный профиль в LocalAppData.

## 2. IMPORT GUITAR — импорт исходников в рабочую библиотеку

1. На главном экране нажмите **IMPORT GUITAR → ОТКРЫТЬ ЭТАП** или откройте меню **01 IMPORT GUITAR → Импортировать гитарные материалы**.
2. При первом импорте выберите базовую папку `Samples`. Manager создаст в ней `Import Sample Guitar`, `FACTORY` и `OTHER`; выбранный путь сохранится.
3. Выберите отдельные аудиофайлы/SFZ/архивы и/или несколько папок исходной библиотеки.
4. Подтвердите копирование. Manager создаёт новую папку пакета `IMPORT_BATCH_...` внутри `Samples/Import Sample Guitar`, сохраняя структуру выбранных папок и имена файлов. Оригиналы остаются на прежнем месте и не изменяются.
5. Каждая копия проверяется по SHA-256. Если копирование, проверка или регистрация завершается ошибкой, текущий пакет откатывается; исходные файлы не затрагиваются. При повторном импорте неизменённых источников уже проверенные копии используются повторно. Если ранее импортированная копия была изменена или повреждена, Manager останавливает повторный импорт и показывает путь к файлу для ручной проверки — не продолжайте сканирование, пока не разберётесь с этой копией.
6. В реестре сохраняются путь к оригиналу, путь к копии, размер, время изменения и SFZ-аудит. Копии в `Import Sample Guitar` затем доступны для **SCAN LIBRARY** и **START HUNTING**.
7. Архивы копируются как исходные файлы, но не распаковываются автоматически.

При повторном импорте, если изменился хотя бы один файл в выбранной папке (или добавился новый), Manager создаёт новый полный пакет с той же структурой каталогов, чтобы SFZ и их зависимости не смешивались между версиями. Предыдущий пакет не удаляется автоматически — он остаётся для сравнения и восстановления. Поэтому после обновления источника SCAN LIBRARY увидит обе версии; перед BUILD LIBRARY проверьте отчёты и вручную решите, какие кандидаты оставить для Factory.

Импорт требует дополнительного места на диске. Не выбирайте саму папку `Samples` или её родительскую папку как источник — это может включить рабочую папку импорта и создать рекурсивную копию. Выбирайте конкретные папки библиотек или отдельные файлы.

## 3. SCAN LIBRARY — инвентаризация без музыкального извлечения

Есть два уровня проверки:

**Быстрое сканирование**
1. Откройте меню **02 SCAN LIBRARY → Быстрое сканирование — только файловая инвентаризация**.
2. Manager обходит папки и читает имена, размеры, даты и структуру.
3. SHA-256, декодирование аудио и музыкальный анализ не запускаются.

**Глубокое сканирование**
1. Нажмите главную карточку **SCAN LIBRARY → ОТКРЫТЬ ЭТАП** либо выберите **02 SCAN LIBRARY → Глубокое сканирование — SHA-256 / SFZ / кэш**.
2. Manager выполняет быстрый обход, глубокую инвентаризацию, проверку форматов, SHA-256, точных дубликатов и SFZ-зависимостей.
3. Акустический анализ и физическое извлечение WAV на этом этапе не запускаются. Повторные проходы используют кэш для неизменённых файлов.

## 4. START HUNTING — полный цикл подготовки библиотеки

1. На главном экране нажмите **START HUNTING → ОТКРЫТЬ ЭТАП**.
2. При необходимости включите полный акустический и ритмический анализ. Для самого лёгкого режима используйте отдельные действия SCAN LIBRARY.
3. Подтверждайте гитарный источник только после реальной фильтрации не-гитарных Piano/Bell/Drum материалов. Без этого подтверждения Manager выполнит инвентаризацию и анализ, но не будет физически извлекать гитарные WAV-кандидаты.
4. Полный цикл включает быструю и глубокую инвентаризацию, акустические кандидаты, поиск повторяющихся ритм-паттернов, извлечение длинных регионов, нот, chord/Power Chord кандидатов и формирование библиотеки-каталога для отдельного VST3.
5. Следите за журналом. Кнопка **ОСТАНОВИТЬ ЗАДАЧУ** передаёт запрос остановки на безопасной контрольной точке; уже созданные staging-кандидаты сохраняются.
6. После цикла изучите отчёты в `UserData/reports`.

Длинные регионы, повторяющиеся рисунки и pitch/chord-кандидаты не считаются автоматически подтверждёнными риффами, тактами, нотами, аккордами или артикуляциями. Это кандидаты для проверки. Все производные WAV и манифесты остаются в `UserData/staging` (или `staging` в source-разработке).

## 5. REVIEW QUEUE — ручная музыкальная и лицензионная проверка

1. Нажмите главную карточку **REVIEW QUEUE → ОТКРЫТЬ ЭТАП** или выберите **04 REVIEW QUEUE → Открыть очередь проверки**.
2. Выберите WAV-манифест и прослушайте производный фрагмент; при необходимости сравните его с оригиналом.
3. Проверьте точные границы, ноты, аккорд, артикуляцию и назначение библиотечной категории только по фактически услышанному материалу.
4. Укажите музыкальные заметки и документальное лицензионное основание, которое действительно разрешает включение и распространение материала.
5. Подтвердите музыкальную проверку и лицензию раздельно и только после выполнения обеих проверок.

Статусы `REVIEWED` и `LICENSE_APPROVED` независимы. Не указывайте выдуманную лицензию, а также название сайта или архива вместо реальных условий правообладателя.

## 6. BUILD LIBRARY — каталог и распределение одобренных ассетов

1. Нажмите главную карточку **BUILD LIBRARY → ОТКРЫТЬ ЭТАП**. Она создаёт/пересобирает проверенный каталог ассетов для отдельного POP PUNK GUITAR ULTIMATE VST3, Performance Manifest, карту высот и отчёты структуры/покрытия.
2. Каталог хранит ссылки на WAV в staging, исходные SHA-256, границы фрагментов и статусы review/license. Непроверенные WAV остаются кандидатами и не становятся автоматически пригодными для воспроизведения.
3. Для просмотра подготовленных WAV откройте **01 IMPORT GUITAR → Браузер подготовленных ассетов для VST3**. Sample Browser — инструмент проверки и предпрослушивания подготовленной библиотеки, а не музыкальный режим Manager или сам VST3-плеер.
4. В Sample Browser выпадающий список показывает категории назначения ассетов для VST3. Это классификация данных библиотеки, а не дополнительные главные режимы Manager. У VST3 остаются два главных режима — **MELODY** и **PATTERN**; **AutoChords** является вспомогательным окном внутри PATTERN.
5. Дополнительные инструменты подготовки доступны в меню **05 BUILD LIBRARY**: Pattern Song Manager и 12-нотная карта высот для AutoChords внутри PATTERN.
6. Физическое копирование в `FACTORY` запускается отдельно через **05 BUILD LIBRARY → Распределить одобренные ассеты**. После подтверждения Manager проверяет все найденные манифесты, копирует только независимо одобренные и прошедшие проверки записи, а ошибки отдельных манифестов записывает и обрабатывает дальше. Это не выборочная ручная отправка одного файла из Sample Browser.

Перед копированием проверяются музыкальное одобрение, лицензия, исходный и производный SHA-256, формат PCM WAV, точные границы и отсутствие конфликтов назначения. Копирование транзакционное; исходные аудиофайлы остаются на месте.

## 7. VERIFY / RECOVERY — проверка и безопасное восстановление

1. Нажмите главную карточку **VERIFY / RECOVERY → ОТКРЫТЬ ЭТАП**. Она запускает аудит staging и `FACTORY`, но сама не копирует файлы.
2. Разберите ошибки, блокировки и предупреждения в итоговом отчёте.
3. Для аудита исходников перед возможной очисткой откройте **06 VERIFY / RECOVERY → Аудит исходников перед очисткой**.
4. Удаление исходников — отдельная опасная операция. Она требует полного аудита, выбора итогового отчёта и двух отдельных подтверждений. Не используйте её в обычном процессе; сначала сохраните независимую резервную копию Samples.

Остальные вспомогательные команды доступны в соответствующих меню: PROJECT — выбор Samples и открытие папок отчётов/staging; REVIEW QUEUE — предпрослушивание и история задач; SETTINGS — переключатели анализа и подтверждения гитарного источника. На главном экране при этом остаются ровно шесть основных действий.

## 8. Настройки для слабого ПК (Core i3-5005U, 8 GB RAM)

В Manager 3.0 установлен щадящий профиль по умолчанию:

- один worker-поток глубокого анализа (вместо двух);
- жёсткий верхний предел — два потока;
- анализатор декодирует аудио блоками по 65 536 кадров;
- для акустического анализа ограничивается моно-представление 90 000 точками в режиме обнаружения, длинные записи прореживаются;
- извлечение ограничено существующими безопасными квотами;
- GUI не выполняет аудиоанализ в главном потоке и получает редкие пакетные сообщения прогресса.

Практические рекомендации:

1. Для проверки структуры используйте только быстрое сканирование.
2. Полный цикл запускайте после добавления/изменения материалов, а не подряд несколько раз без необходимости — SHA-256 cache ускоряет повторные запуски.
3. Если ПК начинает заметно тормозить, остановите задачу, закройте браузер/DAW и повторите полный анализ позже.
4. Не запускайте два экземпляра менеджера одновременно.
5. Не отключайте защиту Windows и не переносите папки приложения во время выполнения.

Лимит 90 000 точек уменьшает нагрузку и сохраняет общие акустические признаки, но может сгладить очень короткие transient-детали. Поэтому результаты остаются кандидатами и требуют прослушивания.

## 9. Защита исходников и лицензий

- Анализ не перемещает, не переименовывает и не удаляет исходные файлы.
- Кандидаты и неподтверждённые материалы остаются в staging.
- Похожесть звучания не означает дубликат. Автоматически объединять или удалять похожие исполнения запрещено.
- FACTORY не должна принимать непроверенные материалы.
- Лицензию подтверждает пользователь на основании реальных условий правообладателя. Менеджер не может сам доказать законность распространения.
- Перед любыми рискованными действиями храните резервную копию Samples.

## 10. Если что-то не работает

1. Не удаляйте staging и reports.
2. Нажмите «Открыть отчёты» и сохраните последний `unified_errors.json` / `unified_summary.json`.
3. Сделайте снимок окна с последней строкой журнала и статусом.
4. Передайте текст ошибки и укажите, какая кнопка была нажата.
5. Не повторяйте удаление/распределение, пока причина ошибки не выяснена.

**Главный безопасный порядок:** IMPORT GUITAR → SCAN LIBRARY (быстрое или глубокое сканирование) → START HUNTING (полный цикл, когда нужна подготовка WAV) → REVIEW QUEUE → BUILD LIBRARY → VERIFY / RECOVERY. Копирование одобренных материалов в FACTORY запускается отдельно через меню BUILD LIBRARY. Для обычного ежедневного использования оригиналы не удаляйте. ## Подготовка каталога для отдельного VST3 и Sample Browser (Manager 3.0)

1. Выберите `Samples` или `Import Sample Guitar`.
2. Для полной подготовки включите тяжёлый акустический/pitch/ритмический анализ и подтвердите гитарный источник только если папка действительно прошла guitar-only фильтрацию.
3. Запустите главную карточку **START HUNTING**. При подтверждённом гитарном источнике Manager подготавливает повторяющиеся ритм-паттерны, chord/Power Chord sample-кандидаты, отдельные ноты и фразы, которые затем могут быть включены в категории подготовленной библиотеки VST3.
4. После аудита staging Manager автоматически создаёт `plugin_asset_catalog.json` и `performance_manifest.json` в папке отчёта текущего запуска. Второй файл содержит структурированные asset bindings и контракт событий для будущего VST3; неподтверждённые музыкальные события и тайминг не генерируются.
5. Откройте **Браузер подготовленных ассетов для VST3**, выберите категорию назначения библиотеки и прослушайте извлечённый WAV-кандидат. Это фильтр подготовленных данных, а не режим работы Manager.
6. Главная карточка **BUILD LIBRARY** или меню **05 BUILD LIBRARY → Собрать каталог ассетов PPGU** пересобирает каталог из текущих staging-манифестов. **Sample Browser** открывает самый свежий каталог.
7. Каталог хранит относительные ссылки на WAV внутри `LibraryManager/staging`, исходные SHA-256 и точные sample offsets. Он предназначен для последующего чтения VST3.

Важно:
- Все автоматически извлечённые WAV остаются кандидатами; прослушивание не означает музыкальное или лицензионное одобрение. При ручной проверке Manager предлагает явно назначить одну или несколько из десяти категорий назначения ассетов для VST3; указывайте только те категории, чьё содержимое вы лично подтвердили. Это классификация содержимого библиотеки, а не дополнительные режимы Manager или дополнительные главные режимы плагина. Это позволяет заполнять STRUMMING, ARPEGGIO, ARTICULATIONS и ENDING без догадок классификатора.
- Chord Analyzer формирует только гипотезы аккорда/Power Chord. Manager дополнительно строит варианты аппликатур для ARPEGGIO по классам высот в предположительном стандартном строе EADGBE. Строй, физическая играбельность, пальцовка, струны и лады остаются NEEDS_MUSICAL_REVIEW/UNKNOWN до ручного подтверждения.
- STRUMMING, ARPEGGIO, ARTICULATIONS и ENDING не заполняются догадками по RMS или простым onset-анализом.
- Runtime-playable в каталоге становятся только WAV с проверенной целостностью, статусами `REVIEWED` и `LICENSE_APPROVED` и явным evidence.
- Каталог не означает, что VST3 уже собран: сам плагин должен реализовать чтение этой схемы и realtime playback.


### Portable / Installer: где хранятся отчёты

В Portable-режиме отчёты полного сканирования, SQLite-кэш SHA-256/аудиоанализа, история задач и staging хранятся в `UserData` рядом с Portable-программой. Если папка программы защищена от записи, используется постоянный профиль в LocalAppData. В установленной версии изменяемые данные хранятся в LocalAppData; папка установки предназначена для файлов программы.
