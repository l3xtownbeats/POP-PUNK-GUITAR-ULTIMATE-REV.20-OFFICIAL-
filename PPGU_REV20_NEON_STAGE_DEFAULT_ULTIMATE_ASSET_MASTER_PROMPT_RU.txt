Главная оболочка организована как премиальная трёхзонная консоль:

- кнопка `SETTINGS`;
- кнопка `SKIN` / Skin Gallery;
- ровная металлическая рамка заголовка, аккуратные разделители и маленькие состояния.

B. LEFT ZONE — FACTORY PRESET BROWSER
- заголовок/верхняя рамка секции как в макете;
- ComboBox `FACTORY PRESET CATALOG`;
- category selector: `ALL PRESETS`, `MELODY`, `PATTERN`;
- поле `SEARCH PRESETS...`;
- список/панель preset browser;
- состояния selection, hover, keyboard focus, disabled, empty/no match;
- не изображай фальшивые 500 готовых playable presets: каталог в коде частичный, поэтому не зашивай ложное число в artwork. Не рисуй неподтверждённые названия пресетов как реальные данные.

C. CENTER ZONE — PLAYING CORE / INSTRUMENT CONTROLS
- две и только две основные музыкальные области/режима: `MELODY` и `PATTERN`;
- не вводи третий основной режим;
- главная группа из 9 rotary controls, расположение по фактическому макету и текущей трёхколоночной сетке редактора;
- подписи главных регуляторов строго такие:
  1. `GAIN`     → APVTS ID `ampGain`
  2. `TREBLE`   → APVTS ID `eqHigh`
  3. `MID`      → APVTS ID `eqMid`
  4. `BASS`     → APVTS ID `eqLow`
  5. `VELOCITY` → APVTS ID `velocity`
  6. `DYNAMICS` → APVTS ID `dynamics`
  7. `SWING`    → APVTS ID `swing`
  8. `HUMANIZE` → APVTS ID `humanize`
  9. `ACCENT`   → APVTS ID `accent`
- каждый регулятор должен выглядеть как реальный высококлассный аппаратный компонент: отдельный корпус, rim, центр, pointer, шкала/markings, controlled highlight, тень и опциональный glow;
- значение выводится отдельным текстовым/цифровым слоем, не зашивать динамические числа в PNG;
- не добавляй декоративные неработающие ручки. Каждый визуальный knob соответствует ровно одному существующему параметру.
- режимы MELODY/PATTERN должны иметь чёткое selected/unselected состояние. `PATTERN` открывает вспомогательную маршрутизацию секций, но не становится отдельным третьим режимом.

D. RIGHT ZONE — AMP & TONE / FX CHAIN
Заголовки: `AMP & TONE` и `FX CHAIN`.
Главный фиксированный список из ровно 7 кнопок/переключателей:
1. `COMPRESSOR` → `compressorOn`
2. `EQ` → `eqOn`
3. `DISTORTION` → `distortionOn`
4. `CHORUS` → `chorusOn`
5. `DELAY` → `delayOn`
6. `REVERB` → `reverbOn`
7. `CABINET IR` → `cabinetOn`

Каждая кнопка — отдельный визуальный элемент, её ON/OFF state обязателен. Переход по клику открывает соответствующую группу параметров FX EDIT. Не добавляй восьмую кнопку в главный FX CHAIN: `FLANGER` существует как отдельная редактируемая группа внутри FX EDIT, но не входит в этот фиксированный список из семи главных переключателей.

E. LOWER PERFORMANCE STRIP / KEYBOARD
- широкая панель статуса/производительности;
- реальный performance display показывает `LIVE HARMONY`, chord text, `SCALE / KEY`, `NOTES HELD`;
- цифровое/информационное оформление не должно изображать неподтверждённые показатели CPU/RAM, если их нет в реальном UI;
- MIDI-клавиатура горизонтальная, диапазон MIDI note 36–84 (49 клавиш);
- отдельные white keys, black keys, separators, hover key, pressed/key-down overlay;
- клавиатура остаётся читаемой при любом состоянии.

F. FOOTER / STATUS
- статус библиотеки: `NO LIBRARY LOADED / LOAD A LICENSED SFZ INSTRUMENT` или реальный динамический статус;
- визуально показать место для статуса загрузки SFZ, но не подменять status текст статической картинкой;
- индикаторы только тогда, когда соответствуют реальному состоянию.

8. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ К ФАЙЛАМ
======================================================================

Форматы:
- PNG RGBA, 8-bit/channel, alpha transparency — основной формат для bitmap assets.
- SVG — иконки, простые формы, тонкие линии, рамки, scalable outlines. SVG должен быть локальным/self-contained: без внешних URL, ссылок на шрифты, скриптов, внешних изображений и небезопасных XML конструкций.
- Дополнительно WebP допускается только для необязательных preview/texture files; не заменяет PNG RGBA там, где нужен alpha и runtime compatibility.
- Не использовать JPEG для прозрачных элементов.

Целевые размеры:
- главный preview: 1024×700 px;
- исходная рабочая геометрия приложения: 1024×700 px;
- минимальное окно: 900×640 px;
- максимальная рабочая область: 1600×1100 px;
- стандартные иконки: 16/24/32/48 px;
- главные rotary: 128×128 или 160×160 px минимум, предпочтительно 192×192 px для source masters;
- маленькие LED: 16×16 / 24×24 px;
- main button plate ориентируй по макету и сохраняй отдельный clean plate без текста;
- panel frames готовить под 9-slice scaling.

Ключевой принцип: каждый asset должен быть самостоятельным. Нельзя выдавать только один PNG, на котором сразу собраны фон, все панели, все ручки, надписи и кнопки. Коллажи допустимы только как отдельные contact sheets/previews, но не вместо исходных раздельных компонентов.

Для каждого bitmap:
- корректный alpha channel;
- прозрачная область действительно прозрачная, а не чёрная/шахматная нарисованная подложка;
- без белого matte/halo fringe по краям;
- без случайных пикселей/артефактов;
- реальный цвет соответствует точной палитре;
- без некорректного crop;
- края и glow не обрезаны.

Для SVG:
- корректный XML;
- viewBox соответствует размерам;
- path/stroke чистые;
- нет внешних зависимостей;
- иконка центрирована и оптически сбалансирована.
